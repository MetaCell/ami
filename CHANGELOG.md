# Changelog
All notable changes to this project will be documented in this file.

We may want to also add it to the Gtihub release information.

Note: We need this file so we can log new features while we are developing instead of having to do it all at once when release happens.

## 1.0.0

### Big changes
- [[migration]](https://github.com/Metacell/ami/commit/c49f7895bc05d4777e713e8a81126ff1abaa71bc) Full JS → TS migration: the entire `src/` tree (99 files) is now TypeScript, with real `three.js` types via the `@types/three` devDependency (`three` itself ships no bundled declarations). Generated `.d.ts` output now carries real types instead of `any`-typed anonymous objects.
- **BREAKING**: [[controls]](https://github.com/Metacell/ami/commit/64936787872b5a1e858f03c297e81ec239409933) Removed `OrbitControl`/`orbitControlFactory`. It was a vendored copy of an old three.js example (see `controls.orbit.js`'s own header), broken since at least the `three >= 0.180` peer dependency bump (`Quaternion.inverse()` was renamed to `.invert()` upstream years ago — construction threw unconditionally), and confirmed to have zero consumers across this repo, `geppetto-meta`, and `natus`. `TrackballControl`/`TrackballOrthoControl` are unaffected and remain the maintained orbit-style controls.

### Fixed
Real bugs surfaced by real types replacing `any` during the migration:
- [[core: intersections]](https://github.com/Metacell/ami/commit/c49f7895bc05d4777e713e8a81126ff1abaa71bc) `aabbPlane`/`rayBox` can return `false` on invalid input; their only callers (`geometries.slice.js`, `rayBox`'s own use inside `core.intersections.js`) dereferenced the result unguarded — a real crash risk on invalid geometry, not just a type nit.
- [[core: intersections]](core/) Same class of bug, one more spot: typing `rayPlaneInBBox`'s `bbox` param (previously `any`) as `CoreUtils.bbox()`'s real return type surfaced that `aabbPlane` itself never checked its own internal `bbox()` call for `false` before using it — unreachable today since `validateAabb` already guarantees a valid box, but a silent crash waiting for that invariant to drift. Added the same guard `rayBox` already had.
- **BREAKING**: [[presets: segmentation]](presets/) Typing `PresetsSegmentation._presets` (previously `any`) surfaced that `addPreset(presetObj)` called `this._presets.push(presetObj)` on what is actually a plain object keyed by preset name (`{Freesurfer: {...}}`, not an array) — it would have thrown at runtime on its very first call. `addPreset` is unused anywhere in this repo, `geppetto-meta`, or `natus`, so this had never been hit. Changed its signature to `addPreset(name: string, presetObj: SegmentationPreset)`, matching how `fetchPreset` already looks presets up by name.
- [[models: stack]](models/) `ModelsStack._sortSopInstanceUIDArraySort` did `a.sopInstanceUID - b.sopInstanceUID` — numeric subtraction of two DICOM UID strings, always `NaN`. Silently made this last-resort frame-ordering fallback (`orderFrames()`, used only when dimensionIndexValues, imagePosition/imageOrientation, and instanceNumber are all unavailable) a no-op. Now compares with `localeCompare`.
- [[loaders: volume]](loaders/) `LoadersVolumes.parse()`'s "no parser for this extension" and "parser constructor threw" branches both called `reject(...)` and then fell through to build a `ModelsSeries` from `volumeParser`, which in both cases was never successfully assigned — a null-dereference inside a `Promise` executor, silently absorbed into a harmless-looking second rejection by Promise semantics rather than surfacing as the error it was. Declaring `volumeParser`'s real type forced the fix: `return` immediately after each `reject()`, same as every other error path in the function already did.
- [[helpers: localizer]](helpers/) `HelpersLocalizer._prepareMaterial()` set `uPlaneColor1/2/3.value` directly to the raw `THREE.ColorRepresentation` (a hex number, string, or `Color`) instead of converting it to a `[r,g,b]` array first, unlike the `color1`/`color2`/`color3` setters right below it, which already do that conversion (documented inline as required since Three.js r180's `setValueV3f` stopped accepting `THREE.Color` for vec3 uniforms). Only reachable if a plane/color pair were ever set before the helper's first `_create()` call, which no current call site does, but the value was silently wrong shape for the shader if it ever ran. Now converts consistently in both places.
- [[models: voxel]](https://github.com/Metacell/ami/commit/c49f7895bc05d4777e713e8a81126ff1abaa71bc) `ModelsVoxel.value` was mistyped as `number`; it's only ever assigned a formatted string (`'NA'` or `.toFixed()`).
- [[widgets]](https://github.com/Metacell/ami/commit/c49f7895bc05d4777e713e8a81126ff1abaa71bc) Several widget/handle methods (`onMove`, `adjustLabelTransform`, `updateRoI`, `updateDOMContent`) were called both with and without their last argument across call sites, silently relying on `undefined` coercing to falsy — given explicit defaults at the one shared declaration instead of leaving it implicit.
- [[parsers]](https://github.com/Metacell/ami/commit/c49f7895bc05d4777e713e8a81126ff1abaa71bc) Dropped a stray radix argument passed to `parseFloat` (`parsers.mhd.js` — `parseFloat` has no radix param, that's `parseInt`-only), an unused endian argument on single-byte `DataView` reads (`parsers.mgh.js` — a single byte has no endianness), and an unused `frameIndex` argument on a series-level DICOM tag read (`parsers.dicom.js`).
- [[helpers]](https://github.com/Metacell/ami/commit/0576daddb9ae999091e939d3c4647a2b22d476ef) Ported from `master`: `SliceHelper._update()` no longer reuses the existing mesh after `aabbSpace` changes. The seed mesh is built in IJK space with an `ijk2LPS` matrix; reusing it for LPS positions applied that transform twice, misplacing the slice relative to its border until a vertex-count change forced a rebuild. Tracked with a new `_meshAabbSpace` field, typed alongside the rest of `helpers.slice.ts`.

### Changed
- [[core]](https://github.com/Metacell/ami/commit/c49f7895bc05d4777e713e8a81126ff1abaa71bc) Deleted dead code found during the migration: `core.pack.js` and `helpers.dummy.js` (both unreferenced anywhere; `helpers.dummy.js` also referenced an unimported global `THREE` and would have thrown if ever instantiated).
- [[helpers]](https://github.com/Metacell/ami/commit/4a9c6a7c87ce0ea12b997705a131df8e1fb9660b) Ported from `master`: size `uTextureContainer` to the actual number of bound textures instead of a fixed 7/14 slots, dropping the 1x1 dummy-texture padding this required — the fixed size cost a wasted `texture2D` sample per unused slot, per interpolation sample, on every fragment. Also collapsed `StackHelper`'s index scroll handler from two full slice rebuilds (`index` then `planePosition`, each triggering `_update()`) into one via a new `SliceHelper.setIndexAndPlanePosition()`.
- [[build]](https://github.com/Metacell/ami/commit/1a113471eab375a22da2321238f3e62a65d7721a) Added a `typecheck` script (`tsc --noEmit`) — `yarn build` alone never verified types, it just ran vite/esbuild. Also dropped `allowJs`/`checkJs` and the `src/**/*.js` include entry from `tsconfig.json`, dead now that `src/` is 100% TypeScript.
- [[specs]](specs/) Converted the remaining `specs/` test files and `vitest.setup.js` to TypeScript, and brought `specs/` under the `typecheck` script (it wasn't in `tsconfig.json`'s `include` before, so even the pre-existing `.ts` specs went unchecked). Tests that deliberately pass malformed input to `core.intersections`/`core.validators` to exercise runtime guards use `@ts-expect-error` at each bad property instead of `as any` — it fails the build if that argument ever stops being a type error, e.g. if the field it targets is loosened to optional, catching test/API drift that a blanket cast would hide. `loaders.base.spec`'s reach into `LoadersBase`'s `protected` internals uses bracket-notation (`loader['_container']`) instead of `as any`, keeping normal property access on `loader` fully typed.
- [[core]](core/) Eliminated every `any` in `src/core/` (was 14). `core.validators.ts`'s 4 validators now take `unknown` and are real type predicates (`objectToTest is Matrix4`, etc.) instead of `(x: any) => boolean` — callers get actual narrowing, not just a boolean. Added `core/core.types.ts` for the `AABB`/`Plane`/`Ray`/`Box` shapes shared between `core.validators.ts` and `core.intersections.ts` (previously duplicated locally in each file since importing between them risked a cycle). `core.utils.ts`'s stack/camera/mesh-touching methods (`getPixelData`, `setPixelData`, `getRoI`, …) get local structural interfaces (`StackLike`, `CameraWithControls`) instead of `any` — a real `ModelsStack`/`THREE.Camera` import isn't possible here without a cycle (`models.stack.ts` already imports `core.utils.ts`), so this is a deliberate boundary, not a shortcut.
- [[geometries]](geometries/) Eliminated both `any`s in `src/geometries/` (`geometries.slice.ts`). `vertices` is now typed `OrderedPoint[]` (exported from `core.utils.ts`, the function that produces them). `(this as any).type = '...'` — working around `@types/three` declaring `BufferGeometry.type` `readonly` for exactly this "subclasses will update this value" case — became `Object.assign(this, { type: '...' })`, which sets it without a readonly-bypass cast.
- [[presets]](presets/) Eliminated every `any` in `src/presets/` (`presets.segmentation.ts`). Added `SegmentationLabel`/`SegmentationPreset` types for the `{color, opacity, label}` shape already used throughout `presets.segmentation.freesurfer.ts`. `get preset()`/`set preset()` needed explicit return/param type annotations to compile once `fetchPreset` returned a real type — the pair intentionally has asymmetric types (get returns preset data, set takes a preset name), which TS only accepts with both sides annotated.
- [[cameras]](cameras/) Eliminated every `any` in `src/cameras/` (`cameras.orthographic.ts`). `_box`/`box(...)` params are now the shared `Box` type from `core/core.types.ts` (the same shape `Intersections.rayBox` already required). `_controls` gets a local `ControlsLike` interface (`target`/`update`/`handleResize`) rather than importing `ControlsTrackball` directly — both `ControlsTrackball` and `ControlsTrackballOrtho` satisfy it structurally, and the camera genuinely doesn't care which; naming one concrete class would be less accurate, not more.
- [[shaders]](shaders/) Eliminated every `any` in `src/shaders/` (the uniform bag / fragment-shader plumbing shared by every helper). Added `shaders/shaders.types.ts`: `ShaderUniform`/`ShaderUniforms` for the `{type, value, typeGLSL, length?}` entries every `*.uniform.ts` returns, and `BaseFragment` (`{_uniforms, _functions}`) for what `shaders/helpers/*` and `shaders/interpolation/*` read/write via `_base`. Dropped `private` on `_uniforms`/`_functions` on all six `*.fragment.ts` classes — they were already reached into from outside the class via `_base` on every real code path (just untyped, via `any`), so `private` was providing no actual encapsulation, only blocking real typing of `_base`.
- [[models]](models/) Pass A of `src/models/` (data fields only — the `merge`/`validate` protocol across all four classes is a separate, deliberately deferred pass). `models.frame.ts`/`models.series.ts`/`models.stack.ts` had 58 `any`s combined; down to the 6 protocol methods still pending. Highlights: `ModelsSeries._stack`/`ModelsStack._frame` are now real `ModelsStack[]`/`ModelsFrame[]` (previously `any[]`) — the single highest-leverage change here, since `loaders/` and eventually `helpers/` consume these directly. Added `models/models.types.ts` (`SegmentationSegment`, `UltrasoundRegion`, `PixelBuffer`) for shapes `parsers/` produces but doesn't itself type yet. Added a public `ModelsStack.numberOfFrames` getter — `ModelsSeries.merge()` was already reaching into `ModelsStack`'s private `_numberOfFrames` from outside the class (silently permitted while both were `any`); real typing caught it, and the fix is a getter, not a cast. Widened `CoreUtils.minMax`'s param from `number[]` to `ArrayLike<number>` since frame pixel buffers are typed arrays, not plain arrays.
- [[models]](models/) Pass B of `src/models/`: the `mergeModels`/`merge`/`validate`/`_validateModelArray` protocol shared by `ModelsBase` and overridden in `ModelsFrame`/`ModelsSeries`/`ModelsStack`. Every real caller passes a `ModelsBase` subclass (never arbitrary untrusted input, unlike `core.validators.ts`), so the base takes plain `ModelsBase` rather than `unknown` + predicates or a generic — subclass overrides narrow the parameter type further (e.g. `ModelsFrame.validate(model: ModelsFrame)`), which TypeScript's bivariant method-override checking permits and which the `_validateModelArray` self-check (`modelArray[i].validate(modelArray[i])`, confirmed original design via `git log`, not drift) relies on via dynamic dispatch. This also typed `specs/models/*.spec.ts`'s `let validXxx;` variables, which had been implicitly `any` (no initializer, no annotation) and so were never actually exercising these signatures despite the earlier specs-conversion pass — deliberately-invalid calls (`merge()`, `merge('whatever')`) now use `@ts-expect-error`, and direct writes to private fields (`frame._imageOrientation = ...`) were switched to the existing public setters they were bypassing.
- [[parsers]](parsers/) Eliminated every `any` in `src/parsers/`. Added `parsers/parsers.types.ts` (`ParserFileData`, the `{url, buffer}` shape `loaders.volume.ts` hands every constructor). Reused `models/models.types.ts`'s `SegmentationSegment`/`UltrasoundRegion`/`PixelBuffer` rather than redefining them, since `parsers/` is what actually produces that data. `parsers.nifti.ts` gets real types for free from `nifti-reader-js`'s own bundled `.d.ts` (`NIFTI1 | NIFTI2`) — no local interface needed. `parsers.mgh.ts`'s hand-rolled binary reader methods (`_readInt`, `_readShort`, `_readLong`, `_readChar`, `_readUChar`, `_readFloat`) return either a `number` or a typed array depending on the `len` argument — a real overload case, not a lazy union — so each got a two-signature overload (`_readInt(len?: 1): number; _readInt(len: number): Int32Array;`) instead of a blanket `number | Int32Array` that would force every call site to re-narrow. `parsers.dicom.ts` (46 `any`s, the largest single file touched in this whole effort) is now built on `dicom-parser`'s own real `DataSet`/`Element` types instead of an opaque `_dataSet: any`; several of its helper methods (`_findStringEverywhere`, `_findInGroupSequence`, `_findFloatStringInGroupSequence`, `imageOrientation`, `imagePosition`, `pixelSpacing`, `stackID`, `frameTime`) mutated one loosely-typed variable through 2-3 different shapes (string → number[], or a DICOM element → its nested dataset) — each rewritten to return at each branch instead, which is what real types require once a variable can't silently hold "whatever type happens to reach this line". Caught one real self-inflicted regression this way before it shipped: an early rewrite of `_findFloatStringInGroupSequence` dropped the original's fallback `null` on a "not found" path, which the DICOM spec suite's `windowWidth`/`windowCenter` assertions caught immediately (271/271 passing again after the fix) — the kind of thing only a full test run catches, not `tsc` alone.
- [[loaders]](loaders/) Eliminated every `any` in `src/loaders/`. `loaders.base.ts` gets a `ProgressBarLike` interface for its injectable progress-bar dependency (defaults to `HelpersProgressBar`, but anything satisfying the shape works) and a `LoaderUrl` type for the string-or-nested-array `url` param `load()` accepts. `loaders.freesurfer.ts`/`loaders.trk.ts` extend `THREE.EventDispatcher` — unparameterized, its `dispatchEvent` accepts no event names at all (`keyof {}`), which is exactly why both used `(this as any).dispatchEvent(...)`; parameterizing `EventDispatcher<EventMap>` with each loader's actual `load`/`progress`/`error` event shapes made the cast unnecessary rather than just hiding it. `loaders.volume.ts`'s `parse()` juggles one `data` object across `{url, buffer}` → preprocessed-with-extension → (for an MHD/RAW pair) merged-with-two-more-buffers before handing it to whichever format parser's constructor `_parser()` picked — typing this surfaced that the "parser not found" and "parser construction threw" branches both fell through to construct a `ModelsSeries` from a `volumeParser` that was never successfully assigned (a null-deref inside a Promise executor, silently swallowed by Promise semantics into a second, redundant rejection); both branches now return immediately after their own `reject()`, matching what every other error path in this function already did.
- [[helpers]](helpers/) Eliminated every `any` in `src/helpers/` (16 files, the last and largest remaining directory). `helpers.material.mixin.ts` — the shared `_createMaterial`/`_prepareTexture` base for `HelpersSlice` and `HelpersVolumeRendering` — now holds a real `ModelsStack | null` and a `ShaderFragmentConstructor`/`ShaderVertexConstructor` pair (`new (uniforms) => { compute(): string }`) instead of `any`; this required a new public `ModelsStack.spacing` getter, since `helpers.stack.ts`'s orientation-spacing calculation was reaching into `_spacing` directly, and several other call sites across `helpers.slice.ts`/`helpers.volumerendering.ts`/`helpers.stack.ts`/`helpers.contour.ts`/`helpers.localizer.ts` were doing the same for `_prepared`/`_packed`/`_minMax`/`_ijk2LPS` — all switched to the public getters `ModelsStack` already exposes for them. Widened `shaders/shaders.types.ts`'s `UniformValue` union to include `THREE.Vector4` (the localizer's plane-equation uniforms are the only `vec4`s in the codebase and were never representable before). `helpers.stack.ts`/`helpers.boundingbox.ts`/`helpers.lut.ts`/`helpers.segmentationlut.ts` drop a few genuinely dead fields (`_dummy`, `_uniforms`, `_autoWindowLevel` on `HelpersStack` — declared, assigned `null` once, never read) found while typing forced a look at every field. The `x/` subdirectory (legacy/demo rendering path: `helpers.x.mesh.ts`, `helpers.x.volume.ts`, `helpers.x.renderer3d.ts`, `helpers.x.renderer2d.ts`) reuses the same `InstanceType<NonNullable<typeof Factory>>` pattern to type instances produced by the `helpersXxx(three)` factory functions without needing a second, parallel type declaration. `helpers.x.renderer2d.ts`'s `addEventListeners`/`removeEventListeners` were passing a third `false` argument to `THREE.EventDispatcher`'s two-argument `addEventListener`/`removeEventListener` (a DOM-style argument that doesn't exist on THREE's API) — silently ignored at runtime, now removed; typing also surfaced that `ControlsTrackballOrtho` (in `controls/`, not typed yet at this point) extends `EventDispatcher` unparameterized, so its own `dispatchEvent`/`addEventListener` calls already relied on internal `as any` casts — worked around here with a local structural interface for the one event this file listens for, since typing `controls/` itself was out of scope for this pass (removed once `controls/` got its own pass, see next entry).
- [[controls]](controls/) Eliminated every `any` in `src/controls/` (`controls.trackball.ts`/`controls.trackballortho.ts`, both vendored/adapted three.js example controls; `controls.ts`, the barrel, was already clean). Both extend `THREE.EventDispatcher` through the same `const Constructor = three.EventDispatcher; class X extends Constructor` factory-injection pattern used throughout `helpers/`, unparameterized — every `dispatchEvent`/`addEventListener` call went through `(_this as any).dispatchEvent(...)`. Typed the local `Constructor` variable as `new () => THREE.EventDispatcher<XEventMap>` (assigning `three.EventDispatcher`'s generic constructor to a variable annotated with a specific instantiation) instead of casting at every call site — same fix already used for `loaders.freesurfer.ts`/`loaders.trk.ts`. `controls.trackball.ts`'s `object` field is `THREE.Camera` (Object3D-level ops only: `.position`, `.up`, `.lookAt()`); `controls.trackballortho.ts`'s is `THREE.OrthographicCamera` (reads/writes `.left`/`.right`/`.top`/`.bottom`/`.zoom`, which only exist there) — matches what `CamerasOrthographic` (itself `extends THREE.OrthographicCamera`) is actually passed as in `helpers.x.renderer2d.ts`. Both files' `handleEvent` method (mirrors the DOM `EventListenerObject.handleEvent` interface, dead code in this repo but a real public method third-party consumers could call) does `this[event.type](event)` for dynamic dispatch onto same-named methods typed via one documented `Record<string, ...>` cast rather than widening the whole method back to `any`. `controls.trackballortho.ts`'s custom `'OnScroll'` event (consumed by `helpers.x.renderer2d.ts`) is now a real map entry (`{ delta: number }`), which let that file drop the structural-cast workaround from the `helpers/` pass above and call `addEventListener('OnScroll', ...)` directly. Also fixed one non-`any` type error `tsc` surfaced once `domElement: HTMLElement | Document` was exercised for real: `handleResize`'s `else` branch (reached only when `domElement !== document`, i.e. always an `HTMLElement`, which `===` narrowing can't express) called `.getBoundingClientRect()`, `Document`-incompatible — cast documented inline instead of left as the pre-existing runtime-safe-but-untyped-as-any gap.
- [[build]](build/) A one-off `tsc --noEmit --noImplicitAny` run (not committed to `tsconfig.json` - a measuring tool, not a standing rule) turned up a few implicit-`any` gaps this effort's plain-text `any` search couldn't see, none introduced by earlier passes: `core.utils.ts`'s `setPixelData` was missing a return-type annotation (now `void | null`, matching its actual `return null;`/fallthrough branches), and `helpers.volumerendering.ts`'s `windowCenter`/`windowWidth` setters indexed `_uniforms.uWindowCenterWidth.value` (typed as the `UniformValue` union) with a numeric literal, which TS can't resolve across a union without narrowing — cast to `number[]` with a comment, matching the array `[center, width]` shape `_prepareMaterial()` actually assigns. The same run found `src/widgets/`'s literal-`any` count (67) badly undercounted its real gap (see the `widgets` entry below) and a handful of missing `.d.ts` shims for third-party packages (`pako`, `nrrd-js`, `math-float32-to-binary-string`, `@cornerstonejs/codec-openjpeg`, `jpeg-lossless-decoder-js`) — pre-existing, not this codebase's code, left alone.
- [[widgets]](widgets/) Eliminated every literal `any` in `src/widgets/` (67 across 17 files), with one deliberate, documented exception. Unlike every other directory in this effort, none of these 17 files declare instance fields — every widget is `this._x = value` with no class-field declaration anywhere, going back to the original JS. That only compiles because `widgets.base.ts`'s `three = (window as any).THREE` factory parameter makes the shared `Constructor` (and therefore the entire `extends` chain every widget builds on) a value of type `any`, which disables TypeScript's member-existence checking for the whole hierarchy - confirmed empirically (isolated repro: a class extending a real, even empty, base errors on any undeclared `this.x`; extending `any` doesn't). Giving that one parameter a real type turns every one of those undeclared fields into a hard compile error across all 13 leaf widgets at once, which is a full field-declaration retrofit, not an `any`-elimination pass - out of scope here, so it stays as a documented exception. Within that constraint, fixed everything real: `WidgetControls.object` is `THREE.Camera`; `WidgetParameter.stack`/`ultrasoundRegions` are the real `ModelsStack`/`UltrasoundRegion[]` types (previously `{}`/`Array<{}>`, invisible placeholders that would have rejected any real property access - only stayed compiling because every read went through the untyped `this._params`); every public method/getter/setter on `WidgetsBase` (the actual facade: `getMouseOffsets`, `getDistanceData`, `getLineData`, `getRectData`, `adjustLabelTransform`, `worldToScreen`, all the `get`/`set` accessors, etc.) now has an explicit, non-`any` signature, which is what actually matters for consumers even though the backing fields stay implicit - a getter's declared return type isn't weakened by an `any`-typed backing field, since `any` is assignable to everything. `widgets.handle.ts` (the shared draggable-point class every concrete widget composes) got the same treatment, plus a real fix: `onStart`/`onMove` were bolting a `.position` property onto `THREE.Raycaster`'s own `Ray` object via `(ray as any).position = ray.origin` to duck-type it as `CoreIntersections`' `{position, direction}` `Ray` shape before passing it back with a second cast - replaced with a small object literal built from `ray.origin`/`ray.direction` directly, which needs no cast at all and doesn't mutate a `THREE.Ray` instance to pretend it's something else. The 13 leaf widgets (`ruler`, `angle`, `ellipse`, `freehand`, `polygon`, `rectangle`, `biruler`, `crossRuler`, `annotation`, `peakVelocity`, `pressureHalfTime`, `velocityTimeIntegral`, `voxelProbe`) all shared one pattern almost verbatim - an untyped `constructor(targetMesh: any, controls: any, params: any = {})` - now `THREE.Mesh`/`WidgetControls`/`WidgetParameter` (reused from `widgets.base.ts`), plus each file's own event-handler params and `InstanceType<NonNullable<ReturnType<typeof widgetsHandleFactory>>>`-typed handle references, matching the `InstanceType<NonNullable<typeof X>>` pattern already used for factory-produced instances in `helpers/x/`.
